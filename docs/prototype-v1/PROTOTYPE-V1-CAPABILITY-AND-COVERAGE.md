## U2–U4 and runtime status (2026-10-10)

- U2: OTP graph read-only GraphQL stop search resolves three distinct Manggarai stops (`LRT Jakarta`, `Mikrotrans`, `KRL`) and seven `Kemang*` named stops, but zero `Village` stops. Do not equate nearby stop with Kemang Village POI. Historical routeability evidence covers seven operator/branch cases on 2026-10-02, not full region coverage. Independent current run of OTP accepted coordinate matrix returned 7 KRL Bogor–Cilebut candidates (540 s, 0 transfers), 12 LRT Kelapa Gading–Manggarai candidates (first 2902 s with 625.77 m walking), 12 MRT Lebak Bulus–Fatmawati candidates (first WALK-only 2964 s; second WALK+MRT 1501 s), and far unsupported coordinate returned `OUTSIDE_BOUNDS` with zero routes. These are OTP-only reads, **not** canonical-binding/API/browser acceptance. Graph was stopped and restarted via `bash scripts/routing/otp-phase4ba.sh start`; health returned `QueryType`. No claim for untested cities or arbitrary dates.
- U3: existing approved source covers OSM-derived topology and OTP-linked stop data, but no accepted POI search/index; smallest interim is explicit validated coordinates (already supported, not a name resolver). POI indexing needs exact source/version/ODbL attribution and update/ingest approval. Do not scrape third-party geocoders.
- U4: `JourneyController.parseRequest` caps response at three; OTP adapter requests at least 12 candidates, planner deduplicates and ranks the accepted set, then slices to three. `preference` controls sorting, not router candidate generation. Frontend `Easiest among shown` is fewest transfers, then least walking, computed over only displayed candidates; not global. Fare stays `UNKNOWN`. Product-wide optimum and backend EASIEST/CHEAPEST not claimed.
- Runtime limitation: macOS APFS reports `compressed,dataless` for several tracked API module files and pnpm dependency files; `read()` returns zero bytes while Git blobs remain intact, so `pnpm --filter @transum-in/api build` fails TS2305 and `pnpm lint` fails on `flatted/cjs/package.json`. This is hydration/filesystem integrity, not source change. API/browser verification and commit remain blocked pending non-destructive hydration/repair. No tracked files reset, no DB writes.
